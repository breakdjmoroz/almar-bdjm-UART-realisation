
# Verilog & SystemVerilog Examples

This directory contains a collection of hardware design and verification examples written in Verilog and SystemVerilog. It is intended for educational purposes, practical exercises, and understanding digital logic design fundamentals.

## Environment Setup

To compile, simulate, and analyze the examples, you need to install the open-source EDA (Electronic Design Automation) toolchain. These instructions are tailored for Debian/Ubuntu-based Linux distributions.

### 1. Install Prerequisites
Open your terminal and run the following commands to install the required tools:

```bash
sudo apt update
sudo apt install iverilog gtkwave verilator
```

**Why these tools?**
*   **Icarus Verilog (`iverilog`)**: An open-source IEEE 1364 (Verilog) and partial IEEE 1800 (SystemVerilog) simulator. It is ideal for functional simulation and executing testbenches.
*   **GTKWave**: A fully featured waveform viewer used to analyze `.vcd` (Value Change Dump) files generated by the simulator.
*   **Verilator**: The fastest open-source SystemVerilog simulator and linter. In this setup, it is used primarily for **static code analysis (linting)** to catch syntax errors, bad practices, and potential bugs directly in the editor before compilation.

### 2. VSCode Configuration
For the best development experience, configure the "Verilog-HDL/SystemVerilog" extension to use Verilator as a linter. 

1. Open this folder in VSCode.
2. Press `Ctrl + Shift + P`, type **Preferences: Open Workspace Settings (JSON)**, and select it. *(Using workspace settings keeps this configuration isolated to this project).*
3. Add the following configuration to the JSON file:

```json
{
    "verilog.linting.linter": "verilator",
    "verilog.linting.verilator.arguments": "-Wall --no-timing --language 1800-2017",
    "verilog.linting.verilator.includeDirs": ["."]
}
```
*Note: The `--no-timing` flag is crucial. It tells the linter to ignore simulation-only delay statements (like `#10`) in testbenches, preventing false-positive errors.*

## How to Run an Example

Follow this standard 3-step workflow to compile, simulate, and view the results of any example.

### Step 1: Compile the Design and Testbench
Use Icarus Verilog to compile your design file (`.v` or `.sv`) and its corresponding testbench into an executable simulation model (named `sim`).

```bash
iverilog -g2012 -o sim <design_file>.v <testbench_file>.v
```
*(The `-g2012` flag enables SystemVerilog features, ensuring modern syntax is supported).*

### Step 2: Run the Simulation
Execute the compiled simulation model using the VVP (Verilog Virtual Processor) runtime.

```bash
vvp sim
```
*Expected Output:* You should see text output in the terminal generated by `$display` or `$monitor` statements in your testbench.


> **Important:** For waveform generation to work, your testbench **must** contain the following lines inside an `initial` block:
> ```systemverilog
> $dumpfile("dump.vcd");
> $dumpvars(0, <name_of_your_testbench_module>);
> ```

### Step 3: View the Waveforms
If the simulation ran successfully, a `dump.vcd` file will be generated in the directory. Open it with GTKWave:

```bash
gtkwave dump.vcd &
```

**In GTKWave:**
1. Expand the module hierarchy in the top-left pane (e.g., `tb_module` -> `uut`).
2. Select the signals you want to analyze (e.g., `clock`, `reset`, `data_out`).
3. Click the **Append** button (or drag and drop) to add them to the waveform viewer.
4. Use the **Zoom Fit** button to adjust the view.

## Cleanup
To remove compiled binaries and waveform files and keep the directory clean, run:
```bash
rm -f sim dump.vcd
```
